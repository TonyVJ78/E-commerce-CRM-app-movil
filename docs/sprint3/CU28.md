# CU-28 — Recordatorios de recompra y notificaciones móviles

Rama `cu28-recompra-push-movil`, acumulativa sobre `cu27-cupones-movil` y `cu26-carrito-movil`. CU-25 permanece incluido. No se modifica `main`.

## Uso

Cliente: Inicio → campana de notificaciones → **Mis notificaciones**. Permite consultar avisos, actualizar deslizando, leer páginas anteriores y marcar un aviso como leído. Al abrir un recordatorio consulta el producto actual; un carrito vuelve a cargar productos/stock desde el servidor y una promoción abre los cupones vigentes. No reconstruye compras desde el contenido de un push. La misma campana ofrece **Mis promociones**.

Empresa: Tiendas → abrir tienda → **Campaña de carrito** / **Cupones y promociones** en las acciones de la tienda. Configura reglas y cupones con vigencia, segmento, monto mínimo y límites. Cliente: Carrito → introducir/aplicar un cupón por tienda antes de pagar. El backend calcula el descuento final tanto en efectivo como con tarjeta.

Las rutas nuevas requieren el backend `cu28-recompra-push-api`. Las ramas publicadas no despliegan automáticamente esas APIs en el servidor configurado en la app. Consultar `docs/sprint3/CU28.md` del backend para las migraciones y `procesar_marketing` periódico. Con autorización se aplicaron las migraciones revisadas en la base compartida y se envió una prueba FCM únicamente al Pixel 8.

## Firebase: preparación sin claves compartidas

Actualización 26/10/2026: ya se configuró el proyecto `kantu-market-si2` y se verificó un envío FCM al Pixel 8. La configuración local y el procedimiento del equipo están en `docs/INTEGRACION-FIREBASE.md`. Cada usuario debe conceder el permiso de notificaciones de Android.

1. Crear/usar el proyecto del equipo en Firebase Console y registrar Android **bo.kantu.kantu_market**.
2. Copiar `config/firebase.example.json` a `config/firebase.local.json` (ignorado por Git) y completar las cuatro propiedades con la configuración pública de la app Android del proyecto. `FIREBASE_APP_ID` es el identificador de aplicación Firebase, no el nombre del paquete Android. No usar una cuenta de servicio.
3. Reconstruir con ese archivo:

```powershell
flutter run -d emulator-5554 --dart-define-from-file=config/firebase.local.json
```

4. Configurar Firebase Admin en el servidor del mismo proyecto, activar `FCM_ENABLED`, abrir la bandeja y pulsar **Activar notificaciones**. El sistema solicita permiso de Android 13+ y registra el dispositivo con autenticación.
5. Probar en primer plano, segundo plano y app cerrada con un cliente de prueba y datos de ese cliente; comprobar destino y lectura. No usar credenciales de producción ni enviar campañas masivas para probar.

Documentación: https://firebase.google.com/docs/flutter/setup y https://firebase.google.com/docs/cloud-messaging/flutter/client

La configuración Android se prepara con `scripts/configurar_firebase.py`. Google Services genera los recursos nativos desde `android/app/google-services.json`; Flutter también admite `FirebaseOptions` desde el archivo local. Ambos archivos de configuración permanecen ignorados por Git. iOS requiere además la configuración APNs del proyecto; no está validado en este avance Android.

Los tokens FCM y payloads no se imprimen en consola. Al cerrar sesión se desactiva el dispositivo y se elimina su token local de FCM. Los destinos se validan y los avisos con otro `cliente_id` se descartan.
