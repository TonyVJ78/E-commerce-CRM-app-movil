# CU-26: campañas y recuperación de carrito en móvil

La rama es acumulativa sobre CU-25. Empresa: Tiendas → seleccionar tienda → Carritos abandonados.
Permite consultar métricas y carritos inactivos, activar/desactivar y guardar la campaña y enviar
un correo de prueba al propietario. No se envían correos reales en las pruebas automatizadas.

Usa las rutas existentes `GET/PATCH /api/tiendas/{id}/campana-carrito/`,
`GET /api/tiendas/{id}/carritos-abandonados/` y
`POST /api/tiendas/{id}/campana-carrito/disparar-prueba/`.
Respeta los límites reales del servidor: 1–72 horas y 0–50 %.

El tipo de notificación `carrito_abandonado` abre el carrito del cliente y vuelve a consultar
la API autenticada. El payload nunca sustituye productos, precios o cantidades del servidor.
Ante un fallo remoto no se presentan compras SQLite como si fueran el carrito del servidor.

La evaluación periódica, el envío y el marcado de recuperación pertenecen al backend.
La recepción push real requiere la configuración Firebase de CU-28.
